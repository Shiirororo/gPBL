# Pull Request（PR）作成ガイド

## 1. 最新のコードを取得する

作業を始める前に、`main`（または開発ブランチ）の最新状態を取得します。

```bash
git checkout main
git pull origin main
```

---

## 2. 作業用ブランチを作成する

機能追加やバグ修正ごとに新しいブランチを作成します。

```bash
git checkout -b <feature_branch>/機能名
```

例：

```bash
git checkout -b feature/login-api
git checkout -b fix/search-bug
```

---

## 3. コードを実装する

担当する機能や修正を実装し、動作確認を行います。

---

## 4. 変更をコミットする

変更内容をステージングし、分かりやすいコミットメッセージを付けます。

```bash
git add .
git commit -m "feat: ログインAPIを追加"
```

コミットメッセージの例

* `feat: 新しい機能を追加`
* `fix: バグを修正`
* `refactor: コードを整理`
* `docs: ドキュメントを更新`
* `test: テストを追加`

この例に従う必要はありません。ご自身のコードコミットに関する情報を提供してください。

---

## 5. ブランチをリモートへプッシュする

```bash
git push origin feature/login-api
```

---

## 6. Pull Request を作成する

機能の実装が完了したら、プルリクエストを作成できます。
GitHub のリポジトリを開き、**New Pull Request** をクリックします。

以下の内容を確認してください。

* Base Branch（マージ先）が正しいこと
* Compare Branch（作業ブランチ）が正しいこと
* 変更内容に問題がないこと

---

## 7. Pull Request の説明を書く

### 例：
以下の内容を記載するとレビューしやすくなります。

#### 概要

今回の変更内容を簡潔に説明します。

#### 変更内容

* ログインAPIを追加
* JWT認証を実装
* ユニットテストを追加

####  動作確認

* [x] ローカルで動作確認済み
* [x] テスト成功
* [ ] ドキュメント更新

#### 関連 Issue

```
Closes #123
```

---

## 8. レビューを依頼する

レビュアーを設定し、レビューを依頼します。

レビューコメントがあれば修正し、再度コミット・プッシュします。

```bash
git add .
git commit -m "fix: レビューコメントへ対応"
git push
```

PR は自動的に更新されます。


---

# ベストプラクティス

* PR は小さく保つ
* 1つのPRでは1つの目的だけを扱う
* コミットメッセージを分かりやすく書く
